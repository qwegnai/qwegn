# 06 — Menu Bar (`@Observable`) & WebUI Telemetry Parity

> Normative specification for `QWMenuBarUI` (`Sources/Apps/QWMenuBar/`), `Qwegn.app` bundling, `QWSettingsCoherence`, and `/ui` parity.

## 1. Observation Architecture (`@Observable`)
- `TelemetryObservable` (`Sources/Apps/QWMenuBar/TelemetryObservable.swift`) is `@MainActor @Observable` (no `ObservableObject` or `@Published`), importing `Observation`.
- Internal timers, `Task` handles, `Process` handles, and stale-fetch tokens (`pollTimer`, `loggerSubscriptionId`, `serverProcess`, `lastKnownServerPid`, `nextLogSequence`, `isPopoverVisible`, `isLogWindowVisible`, `dashboardStreamTask`, `logStreamTask`, `lastDashboardStreamAt`, `dashboardGeneration`, `engineInfoGeneration`, `lastErrorPhase`) are annotated `@ObservationIgnored` so non-UI housekeeping never triggers SwiftUI invalidation.
- `init(startServices: Bool = true, enableAutoLifecycle: Bool = true, initialSettings: QWServerSettings? = nil)` supports hermetic unit testing (`startServices: false` / `enableAutoLifecycle: false`) while preserving zero-argument production startup (`TelemetryObservable()`).
- Views accept plain `var telemetry: TelemetryObservable` (`CupertinoTelemetryView`, `SettingsView`, `LogViewerWindow`) or `@Bindable var telemetry: TelemetryObservable` where `$telemetry.*` bindings are required (`SettingsMenuBarAppearanceView`).
- `QWMenuBarApp` runs as a pure `@MainActor` AppKit entrypoint (`NSApplication.shared.run()`) retaining `AppDelegate`, with no SwiftUI `Settings { EmptyView() }` scene, installing App/Edit/Window `NSApp.mainMenu` shortcuts and routing local key events via `QWMenuBarShortcutRouter`.
- `AppDelegate` updates `NSStatusItem` through `withObservationTracking` (`observeStatusItem()`), re-evaluating only when properties read by `menuBarStatusState` or `menuBarStatusTitle` mutate.

## 2. Single-Source Telemetry & Honesty Invariants
Both `Qwegn.app` and `QWServer` (`/ui` backed by `Sources/Apps/QWServer/Resources/{controlbar.html,logo.svg,css/{base,panels,chat,decisions}.css},js/{state,dashboard,markdown,chat-presets,chat,decisions-views,decisions,actions,settings,updates}.js}`) render from `QWDashboardViewModel` (`QWDashboardBuilder`):
- **Catalogue lockstep:** Every card ID read in `QWMenuBar` (`TelemetryCards.swift`) belongs to `MenuBarCardCatalogue.ids` (including optional `decisionSidecar` card rendering `decisionSidecarVision`, `decisionSidecarArchetype`, and `decisionSidecarPromptTokens` strictly inside the `440pt` popover width with `MarqueeText` for model titles); `/ui` cards belong to `QWDashboardBuilder.cardSpecs` (including `#decision-telemetry-card` on `Monitor`). `0`-output-token decision calls must never inject synthetic `0.0 tok/s` samples into `decodeRateSeries`.
- **Zero fabricated state, coherent Decision UI & offline modular assets (`ADR-014`):** Missing metrics render `—` with `card.reason` tooltips; UI code must never read `engineInfo` / `settings.modelName` for active model titles or synthesize `"Idle"` / `"Stopped"` fallbacks when disconnected (`MenuBarRendererParityTests`, `DashboardRendererParityTests`, `QWTelemetryHonestyTests`, `QWDecisionsWebUIParityTests`, `QWModernWebPlatformParityTests`, `QWCliGuiWebParityTests`). All `/ui` HTML/CSS/JS files remain `<= 800` lines, copied via `Package.swift` `.copy(...)`, and served strictly offline (`Cache-Control: no-cache`, zero `https://` CDN links), adopting `ADR-014` modern web platform controls: ARIA `role="tablist"` / `role="tab"` / `role="tabpanel"` with defensive `switchTab` `aria-selected`/`tabindex` sync, roving `ArrowLeft`/`ArrowRight`/`Home`/`End` keyboard navigation, single-row horizontal tab scroll with Forced-Colors-safe `border-block-end: 2px solid currentColor` active indicator, shared `dialog:modal` + `dialog::backdrop` scroll containment (`overscroll-behavior: contain` + `html:has(dialog:modal)`), `closedby="any"` (`#modal-switch-model`, paired with Safari coordinate-bounded `pointerdown`/`pointerup` light-dismiss fallback) and `closedby="closerequest"` (`#modal-memory-pack`, `#modal-update`, paired with `cancel` busy guards), `command="close"`/`commandfor` invokers with `<= 15`-line local JS fallback, and `@container` size-aware queries (`container-type: inline-size` on `.tab-pane`, `.card-panel`), including:
  - `?tab=decisions` Workbench (`js/{decisions-views,decisions}.js`, `css/decisions.css`) with strict HTML escaping, preset library, `SystemOne` / `OpenAI Decisions` / `Native` / `Laya` / `MCP` wire dialect selector, threshold & `always_emit_box` controls, live SDK snippet generator, sidecar load/unload controls, and SVG bounding-box visualization.
  - `?tab=chat` live `Sidecar` status pill, per-turn `X-Qwegn-Decision-Route` auto-routing badge, and one-click `Decisions →` context handoff (`js/chat.js`, exposed via CORS `Access-Control-Expose-Headers`), plus `Models` Decision capability badges & `"Load Sidecar"` quick-mount button (`js/actions.js`).
  - Smoke Probe Markdown output (`js/markdown.js`) renders offline with strict HTML escaping, URL scheme filtering, code-block copy buttons, and `Raw` / `Rendered` toggle, and the dedicated Chat workspace (`?tab=chat`, `js/{chat-presets,chat}.js`) persists multi-turn sessions/presets strictly in browser `localStorage`, patches streaming turns in place (`updateStreamingChatTurn`) with smart auto-follow scroll latching that unlocks immediately when the user scrolls up (`handleChatTranscriptWheel`, `handleChatTranscriptScroll`, `#chat-scroll-bottom-btn`), keeps reasoning disclosures collapsed by default unless explicitly expanded by the user (`handleChatThinkingToggle`) with rotating dimmed status quips during active reasoning (`CHAT_REASONING_QUIPS`, `.md-thinking-quip`), streams SSE via `/v1/chat/completions`, applies preset harness profiles and `.qwcache` `QWMemoryPack` workspace auto-discovery/inspection/live SSE indexing/mounting (`/v1/memory/inspect`, `/v1/memory/index`, `/v1/memory/mount`, `/v1/memory/unmount`, `#modal-memory-pack` covering `missing`, `wrong_model` with `Switch & Mount`, `stale` with `Update & Mount` / `Mount Existing with Live Delta`, and `ready`), exposes per-session knobs/tools/vision attachments, emits standardized Chat-to-Engine request metadata (`X-Request-ID`, `X-Session-ID`, `session_id`, `cache_prompt`, `prompt_cache_key`/`cache_salt`, `store`, `metadata.{workspace_path,use_memory_pack,exact_speculation,preset_id}`, bridged uniformly across `/v1/chat/completions` and `/v1/messages`, `QWEngineDriver` (`PrefixCache` + `QWHyperStreamRuntime` `FNPrefixCache`) prefix caches, and `QWRequestRecord.config`), and syncs default `systemPrompt` edits back to `/v1/settings`.
- **Cross-phase sparkline continuity without synthetic values:** `QWEngineTelemetryRegistry` preserves `nil` on unmeasured slots (`1 Hz` decode-only slots stay `nil` in `prefillRateSeries`), while `QWSparklineGeometry` and `/ui` `updateSparkline` bridge `nil` slots only when the companion phase holds a positive sample on the same timestamp, keeping `Prefill`/`Decode` lines continuous across turns and still breaking on true dual-nil gaps.
- **Layout bounds & running-text marquee:** `CupertinoTelemetryView` locks its root popover frame to `440pt` (`420pt` inner content width with `10pt` concentric outer padding and `8pt` inter-card spacing, `.clipped()`), while `headerSection` and `loadedWeightsCard` action stacks hold `.layoutPriority(1)`. Unavailable metrics retain `—` inside the fixed slot rather than collapsing columns. Inside the popover (`TelemetryCardPrimitives.swift`, `TelemetryCards.swift`), `heroMetricColumn` locks `"tok/s"` and row height via hidden `"999.9"` / `"9999.9"` templates (plus `minHeight: 15` on the header badge row), `modeBadge` holds `minWidth: 28`, bounded numeric `inlineMetricCell` values right-align to fixed field widths, and `prefillProgressBarRow` remains permanently visible with fixed height across idle, prefill, and decode (`%3d%%` when active, `"—"` when inactive). In `/ui`, `#prefill-banner` (`controlbar.html`, `css/base.css`, `js/dashboard.js`) stays permanently visible with fixed height and neutral idle chrome across idle, prefill, completion, decode, and disconnected states so Monitor cards never shift vertically.
- **Lifecycle boundary & restart coherence:** `QWSettingsCoherence` classifies every setting into `.live` vs `.serverRestart`, keeping all 6 decision knobs (`decisionModelPackPath`, `decisionComputeUnit`, `decisionLoadVision`, `decisionDefaultScoreReadout`, `decisionDefaultTruncation`, `decisionAlwaysEmitBox`) and `reasoningEffort` (`off`/`low`/`medium`/`high`/`xhigh`/`auto`) synchronized across CLI (`KnobOptions.swift`), `/v1/settings`, `Qwegn.app` (`SettingsView.swift`), and WebUI (`js/settings.js`). Server header actions use `restartServerProcess()` / `toggleDaemon()`; model actions stay inside `RESIDENT MODEL`.

## 3. Co-Bundled Binary, Updates & Packaging
- **Check for Updates (`QWUpdateController`, `SoftwareUpdateWindow`, `SettingsView+Updates`, `js/updates.js`):** `QWUpdateController` (`@MainActor @Observable`) runs `On launch & daily` checks by default (configurable in `Settings -> General` via `.live` `updateCheckSchedule`, honoring `QWEGN_NO_UPDATE_CHECK=1`). `TelemetryCards.headerSection` shows a compact `↑ vX.Y.Z` / `↓ NN%` / `✓ vX.Y.Z` header pill (`+0 pt` popover height), opening the dedicated `Software Update` window (`500×420`, `identifier: qwg.updates`, accessible from App Menu `Check for Updates…` and `⌘W`-dismissible) with Markdown release notes, CryptoKit SHA-256 verification, active-inference guard, and `.pkg` receipt vs portable/source fallback. In `/ui`, `js/updates.js` mirrors this with `#header-update-pill` + `#modal-update` talking strictly to local `/v1/update*` routes (zero `https://` literals).
- `Package.swift` splits reusable views/state into `QWMenuBarUI` (`L8.5`, unit-tested by `QWMenuBarTests`), isolates AppleSMC ABI + LaunchDaemon IPC into `QWSMCHelper` (`L0.5`, zero engine dependencies) and the minimal `qwg-smc-helper` executable (`L8.0`), and keeps `qwg-menu` (`L9.0`, `Sources/Apps/QWMenuBarEntry`) as the thin `@main` executable.
- `Scripts/build_app.sh` embeds and code-signs release `qwg`, `qwg-smc-helper`, and `Contents/Library/LaunchDaemons/ai.qwegn.smc-helper.plist` inside `Qwegn.app` so `TelemetryObservable` launches the matching signed sibling engine binary and `Settings -> Performance -> Enable Fan Control…` / `qwg fan-helper install` enable non-root fan writes over `/var/run/qwg-smc.sock` (`OK`/`ERR` protocol replies, hardware `[minRPM, maxRPM]` clamping with `1000 RPM` floor, `15 s` dead-man watchdog auto-restore, `LOCAL_PEERCRED` auth, and clean removal via `Scripts/uninstall.sh`).
