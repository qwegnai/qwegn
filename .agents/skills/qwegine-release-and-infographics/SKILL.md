# Qwegn Benchmarks, Infographics & Release Runbook

## 1. Presentation SVG & Retina PNG Infographics

Every benchmark or architecture infographic in `assets/qwegn_*.svg` and `~/.qwg/models/*/media/` follows five invariants:

1. **Header & Machine Card:** Place the **Qwegn inference engine logo badge in the top-right corner** and include the exact **inference machine specification card** (`Apple M5 Max · Mac17,6 · 18-Core CPU · 40-Core Apple10 NAX GPU · 128 GB Unified Memory · 585 GB/s DRAM · 950 GB/s SLC · macOS 26.2+`).
2. **Evergreen Current-State Metrics Only:** Infographics present **current canonical model and engine performance** — record `before -> after` deltas, legacy pack baselines, and speedup multipliers against retired fallbacks in `CHANGELOG.md` and `docs/tuning.md` only, never inside `assets/qwegn_*.svg` or `~/.qwg/models/*/media/`.
3. **SVG 1.1 Text Halos (No `paint-order="stroke"`):** macOS CoreSVG / `NSImage` ignores SVG2 `paint-order="stroke"` and draws dark strokes *over* text fills. Render chart value halos as two stacked `<text>` elements: background `<text fill="none" stroke="#0b1120" stroke-width="3.5" stroke-linejoin="round">` + foreground `<text fill="#...">`. macOS CoreSVG also ignores `x="..."` overrides on nested `<tspan>` elements inside translated `<g>` groups and collapses consecutive ASCII spaces; keep bullet rows as plain single-spaced text (`• Label: value`) so Retina PNGs match browser/GitHub SVG layout identically.
4. **Mandatory Visual Verification (`2×` Retina PNG):** Rasterize every touched `.svg` at `2×` scale via `swift -e 'import AppKit ...'` (`NSImage` + `NSBitmapImageRep` with `pixelsWide = width * 2`, `rep.size = image.size`; do not rely on Python `import AppKit`, which is absent from Homebrew/Xcode Python), inspect the rendered `/tmp/*.png` with `read_file`, and delete the temporary `.png` before committing — verifying zero pill `<rect width>` clipping, zero label collisions, and clean axis clearance.
5. **Model-Pack Media, Header Verification & Multi-Variant HF Sync:** Verify binary/sidecar container magic and exact tensor formats directly against `Sources/`, QWP1 footer JSON (`QWP1` magic, 8-byte LE footer size at offset `4`, JSON at `length - size`), or `.venv-oracle/bin/python Scripts/quantize/audit_release.py --release <dir>` (an older `/usr/local/bin/qwg inspect` maps mixed planes to `"q4g"`, and use on-disk headers such as `QLSA` v1 `model.qlsa`, never invented tags). When publishing or updating Hugging Face packs across multiple variants of a model family (e.g. `QWP-Fast` and `QWP-Cand5`), run `hf repos create <org>/<repo> --type model --public --exist-ok` (not `hf repo create`) and `HF_HUB_DISABLE_PROGRESS_BARS=1 hf upload ... > out/*.log 2>&1` sequentially so HF Xet deduplicates shared expert/sidecar chunks, generate/upload matching `model.qlsa` via `qwg lsa-convert` when applicable, copy updated per-model `media/*.{svg,png}` and `LICENSE` cleanly, sync `~/.qwg/models/<pack>/README.md` + repo docs (`README.md`, `CHANGELOG.md`, `docs/*.md`), keep `~/.qwg/models/<pack>/assets/*` untouched, and confirm `hf models info` lists all expected files (`model.qwp`, sidecars such as `dspark.qwp`, `README.md`, `LICENSE`, `media/`, `assets/`).

## 2. Full `llmprobe` Server Qualification (`qwg serve`)

1. **Quiet-GPU Execution & Preserved Reports:** On an idle GPU (`0%/0%`), start `qwg serve` on an isolated loopback port (e.g. `18299` to avoid `:8080` conflicts) with `--context-tokens >= 40960` (not `32768`: `llmprobe`'s `~32.8k` scaling rung sends `32,865` tokens) and invoke `llmprobe` (or `/opt/homebrew/bin/node ~/Developer/ai/llmprobe/bin/dist/llmprobe.mjs <base-url>` if absent from `$PATH`) with `--full --eval --eval-suite code --reasoning off` (note `--full` omits the `100`-question code eval unless `--eval` is passed), writing JSON/HTML outputs directly into `out/llmprobe/`.
2. **Zero-Error & Sustained-Load Audit:** Verify `0` HTTP/transport errors across `conformance`, `capability`, `agentic`, `fidelity`, and `bench`, steady `20m+` `loadDrift` (no UMA residency paging dip), deduplicated constrained tool-delimiter IDs (`"special": false` tokenizers), and clean parallel `<tool_call>` splitting.

## 3. Worktree `make ci`, Version Bump & Cleanup Checklist

1. **Worktree Goldens, Fixtures & CWD Discipline:** Inside `.worktrees/<task>`, `run_command` always starts in the primary checkout (`<repo-root>`), so prefix every shell command with `cd <worktree> && `. Symlink `.venv-oracle` (`make goldens`), `Scripts/spike/out` (gitignored `5.5 GB` golden fixtures), and `out/vision_decision_oracle` (vision decision oracle fixtures) from `<root>`, and `rm -f .venv-oracle Scripts/spike/out out/vision_decision_oracle` before `git commit` or `git worktree remove`.
2. **Release-Only Bump Trigger & Canonical Version Locations (`publish_release.sh` Hygiene):** Merging to `master` never bumps the version — feature/fix sessions record changes under `## [Unreleased]` in `CHANGELOG.md` and leave `QWVersion.current` and every release artifact untouched. Bump only in one dedicated release-preparation commit, created solely when the owner explicitly requests publishing a release, choosing the level by the significance of everything accumulated since the last tag (fix/cleanup = patch, feature = minor, breaking/major milestone = major). In that commit, rename `## [Unreleased]` to `## [X.Y.Z] - YYYY-MM-DD` and keep `Sources/Foundation/QWCore/QWVersion.swift`, `CHANGELOG.md`, `README.md` (header badge, headline table, and BibTeX `version = {X.Y.Z}`), `CITATION.cff`, `assets/qwegn_engine_bento.svg` (top pill + footer), and `docs/tuning.md` (ledger row) synchronized. Never use bare `@[A-Za-z0-9_.-]+` tokens anywhere in `CHANGELOG.md` or GitHub release notes — neither context shorthand (`at 4K` / `at 1M`, never `@4K` / `@1M`) nor Swift attribute names (avoid `@Observable`/`@MainActor`) — so `publish_release.sh` and GitHub never treat `@<token>` as a mention or contributor. Both `Scripts/publish_release.sh` (gitignored, primary checkout only) and `.github/workflows/release.yml` extract only the top `## [X.Y.Z]` block — when multiple releases have landed since the previous GitHub tag, include a `### Cumulative Highlights Since Previous Public Release (vA.B.C -> vX.Y.Z)` subsection inside `## [X.Y.Z]` with zero bare `@` tokens. Remove stray untracked files (so `clean_src` sees empty `git status --porcelain`), refresh primary-checkout oracle fixtures not covered by `generate_goldens.sh` (e.g., `.venv-oracle/bin/python Scripts/oracle/vision_decision_oracle.py`) before publishing, and never force-push public tags: if GitHub Actions `release.yml` fails after push, fix in a worktree, bump patch `X.Y.(Z+1)`, publish the new tag, and mark the superseded release `--prerelease` with a banner.
3. **`1M`-Context Qualification on `80+ GiB` Packs:** Validate `1M` (`1,048,576`) UMA admission & residency (`planned <= available`, `0` steady-state allocations) with a deterministic short-prompt run paired with `16K / 128K / 300K` 3-needle passkey sweeps; avoid multi-hour full `1M`-token prefills unless explicitly requested.
4. **Merge, Release Binary & Artifact Hygiene:** Park any live `Qwegn.app` / `qwg serve` before `make ci` (quiet GPU & free `:8080`). Note that `Scripts/ci.sh` prints `tail -5` of `swift test` on pass (showing only the Swift Testing `0 tests in 0 suites` trailer), so run `make test` directly whenever you need exact XCTest suite/case counts for `docs/tuning.md` or release notes. After `make ci` passes (`0` warnings, `0` style/kernel violations), merge into `master`, run `make build` on `master`, verify `./.build/release/qwg --version`, `./.build/release/Qwegn.app/Contents/MacOS/qwg --version`, and `/usr/bin/codesign --verify --deep --strict .build/release/Qwegn.app`, inspect `git worktree list` and delete only your own `.worktrees/<task>` (plus any baseline worktree you created) and feature branch (never unrelated sibling worktrees), clean temporary `/tmp` / `scratch` logs while **preserving `out/llmprobe/*.json`**, and relaunch `Qwegn.app` + verify `/v1/engine/info` if it was running.
5. **SwiftPM Resource Bundle `CFBundle` Normalization (`qwegine_QWServer.bundle`):** Xcode 26 `swift build` emits flat `qwegine_QWServer.bundle` directories without `Contents/Info.plist`, which `codesign` rejects with `bundle format unrecognized, invalid, or unsuitable`. Always normalize `qwegine_QWServer.bundle` into a canonical `Contents/Info.plist` + `Contents/Resources/` layout (`normalize_resource_bundle` in `Scripts/build_app.sh` and `Scripts/build_pkg.sh`) and sign nested `Contents/Resources/*.bundle` before signing `Qwegn.app` in both local (`Scripts/publish_release.sh`) and GitHub Actions (`.github/workflows/release.yml`) release flows.
6. **Post-Merge HF Source Cache Cleanup (When Requested / After Pack Qualification):** Once code and pack qualification have landed on `master`, remove the upstream BF16 cache repo with `hf cache rm model/<org>/<repo> --dry-run` followed by `hf cache rm model/<org>/<repo> --yes`, and verify `~/.qwg/models/<pack>/model.qwp` remains intact.
7. **Post-Publish GitHub-Compiled Release Verification (`release.yml` `--clobber` Audit):** Because `.github/workflows/release.yml` builds on `macos-26` and overwrites local `publish_release.sh` uploads with `gh release upload --clobber`, never certify a release until GitHub Actions finishes:
   - Watch both `release` (tag `vX.Y.Z`) and `ci` (`main`) via `gh run watch <id> --repo qwegnai/qwegn --exit-status`. If simultaneous pushes hit a 15m hosted-runner queue timeout (`jobs[].steps == []` in `gh run view --json jobs` and `"not acquired by Runner of type hosted"` in `gh api repos/qwegnai/qwegn/check-runs/<job-id>/annotations`), rerun `release` solo first and `ci` after `release` completes.
   - Confirm `gh release view vX.Y.Z --repo qwegnai/qwegn --json assets` shows `updatedAt` timestamps strictly after local `publish_release.sh` completion, then download `qwegn-vX.Y.Z-macos-arm64.tar.gz`, `Qwegn-X.Y.Z-macos-arm64.pkg`, and `SHA256SUMS.txt` into a scratch directory.
   - Verify: (a) `shasum -a 256 -c SHA256SUMS.txt` passes; (b) `xcrun -sdk macosx metal-readobj --headers` reports `PlatformMajor: 26`, `PlatformMinor: 2` (or newer) on `kernel.metallib`, `kernel_std.metallib`, and `Qwegn.app/Contents/Resources/kernel.metallib`, and `strings kernel.metallib | grep metalfe-` matches the GitHub Actions Xcode toolchain rather than the local host; (c) `pkgutil --expand-full` (locating metallibs via `find pkg_expanded -name "kernel*.metallib"`, since distribution `.pkg` bundles place them under `pkg_expanded/<Component>.pkg/Payload/...`) shows byte-identical `shasum -a 256` between `.pkg` and `.tar.gz` metallibs; and (d) the extracted `qwg` (`--version == X.Y.Z`) + `QW_METALLIB=<extracted>/kernel.metallib` passes a direct NAX GPU probe and sequential greedy/serve smoke checks on a quiet GPU before cleaning up scratch artifacts.
8. **Co-Runner-Safe Publish & Post-Release `main`-Only CI Hotfix:** Check `pgrep -fl "qwg|Qwegn"` before running `./Scripts/publish_release.sh`; only pass `--skip-ci` after verifying `./Scripts/publish_release.sh --dry-run` on an already-gated release commit when a local co-runner occupies the GPU. If `release.yml` and its downloaded artifacts succeed while `ci.yml` fails on `main` (or another session has already merged newer commits onto `master`), fix the issue in a clean worktree, merge to `master`, and pass local `make ci`, then apply **only** that fix commit (`git -C <master> show --format= <FIX_SHA> | git -C ~/Developer/ai/qwegine-publish apply`) onto `qwegine-publish` `main`, confirm `0` `$HOME` leaks, commit, and `git push origin main` (without pushing a tag or running `publish_release.sh`) before confirming `gh run watch <ci-run-id> --exit-status` green.
