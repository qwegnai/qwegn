# Contributing to Qwegn

Thanks for looking at Qwegn. This guide covers how changes are proposed, checked, and merged.

## Getting set up

```bash
make init   # toolchain check, Python venv, synthetic goldens (about 4 minutes)
make ci     # build, lint, tests, CLI smoke test
```

`make init` needs macOS 26 on Apple Silicon, Xcode 26 or newer, Swift 6.2 or newer, and Python 3.13. It checks each one and tells you what is missing.

## Proposing a change

1. Open an issue first for anything larger than a small fix, so the design can be discussed before code is written.
2. Fork the repository and create a branch from `main`.
3. Make the change. Keep commits focused, and write each message in the imperative mood (`fix: keep the KV pool when a request is cancelled`).
4. Run `make ci` locally. A pull request whose CI fails will not be merged.
5. Open a pull request against `main` and fill in the template.

Only the repository owner merges to `main` and creates releases. Every pull request needs one approving review from the code owner (see `.github/CODEOWNERS`) before it merges.

## Rules the code must follow

These are enforced by `make lint` and `make ci`:

- No source or test file is longer than 800 lines.
- A file header is at most 7 lines.
- A comment block before a declaration is at most 3 lines. Longer design notes belong in the commit message or the pull request, not in the source.
- A `QWModelGeometry` parameter has no default value, so every caller states the model geometry it uses.
- Every Metal kernel in `Sources/QWMetal` must be reachable from a Swift dispatch site.

## Tests

- Tests read only the goldens that `make init` generates, never files from outside the repository and never model weights.
- A test that needs a model pack must skip with `XCTSkip` and a reason. It must not return early and pass silently.
- Performance tests run only when `QW_PERF_GATE=1` is set, through `make perf`.
- Run the suite serially with `make test`. GPU test bundles are not safe to run in parallel.

## Goldens

Golden fixtures are generated by scripts in `Scripts/oracle` and `Scripts/flashnext`. Do not commit generated fixtures. If you change a generator, run `make goldens` and check that the tests still pass.

## Code style

- Swift: follow the existing module layout (`Foundation`, `Operators`, `Subsystems`, `Runtime`, `Apps`).
- Metal: one kernel family per file under `Sources/QWMetal`.
- Python: standard library and the pinned packages in `requirements.txt` only.

## Reporting security issues

Do not open a public issue for a security problem. See [SECURITY.md](SECURITY.md).

## Conduct

Participation is governed by the [Code of Conduct](CODE_OF_CONDUCT.md).
